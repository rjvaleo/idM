# Movies and Standard MIDI Files

**Source of truth:** M 2.7 manual Chapter 12 and Chapter 15's Conducting Window
reference in [`../reference/M27.pdf`](../reference/M27.pdf).

## Manual behavior

A Movie is the MIDI output generated by an M performance. The user arms Movie
before Start; the Movie button remains highlighted while output is captured.
Stop ends capture and un-highlights Movie. A completed take enables **File ▸
Save Movie As Midi File…**. Import can later read a MIDI file into the selected
Pattern Position or preserve it as an independent Sequence whose Conducting
button acts as play-enable/mute.

## Implemented recording model

- Movie is a separate consumer of the planner stream; it does not scrape Midi
  View and does not record Pattern Editor audition notes.
- The Conducting Movie button arms a new take. The previous completed Movie is
  retained until the armed take receives planner output.
- Planner output starts recording. Notes retain Voice, channel, pitch,
  velocity, musical onset, and duration.
- The shared 960-PPQN transport is the canonical timestamp. Pause wall time
  therefore creates no hole in the Movie, while tempo changes are retained as
  tempo-map events at the first affected tick.
- Stop finalizes a non-empty take and disarms Movie. Clicking Movie again also
  finishes/cancels the armed take without destroying the previous Movie.
- New and Open clear transient Movie state. Movie persistence will be added
  deliberately with the next document-format version rather than silently
  changing `ProjectDocumentV2`.

## Standard MIDI File export

**File ▸ Save Movie As Midi File…** is enabled only when a completed Movie
exists. Export is deterministic SMF format 1:

- one conductor track containing tempo meta-events;
- one MIDI track per used Voice;
- 960 PPQN resolution;
- original 1–16 output channels converted to MIDI's 0–15 status nybbles;
- Note Off ordered before a retriggering Note On at the same tick;
- velocity, pitch, channel, onset, and duration clamped to valid MIDI data.

The browser downloads `M Movie.mid` for an untitled project or
`<document stem> Movie.mid` for a named project.

## Verification and remaining scope

The pure recorder and byte encoder are pinned by deterministic tests, including
arming/finalization, chord and Voice retention, pause-gap exclusion, tempo-map
changes, exact SMF structure, retrigger ordering, clamping, and filenames.

Still open in P5:

- MIDI-file parsing and import choices for chords, timing, rests,
  quantization, and source channels;
- import into Pattern Positions;
- independent Sequence storage, playback, and play-enable/mute;
- editable multitrack Movie presentation and document persistence.

The Patterns, Transport, and Conductor parity audit is complete; see
[`PATTERNS_TRANSPORT_AUDIT.md`](./PATTERNS_TRANSPORT_AUDIT.md). MIDI import is
the next slice.
