# M Classic — engine (Rust)

The port of `src/engine` from TypeScript. One engine, three consumers: `wasm32`
for the browser app, a static library for the plugin and the standalone.

**Status: started, not usable.** `rng` is ported and conformant. The planner,
tempo map, transforms and document model are not. The TypeScript engine remains
the only working one.

## The gate

The port is not judged by review or by ear. `mulberry32` is `u32` arithmetic
that reproduces exactly, so the TypeScript engine can be pinned to bytes and
this one required to reproduce them.

    src/engine/__goldens__/rng.txt         raw u32 draws, the derived helpers,
                                           and BrownianWalk as f64 bit patterns
    src/engine/__goldens__/voices-*.trace  every planned note for a fixed
                                           project, seed and span

Both are generated by the real TypeScript implementation:

    npm run goldens         rewrite them
    npm run goldens:check   fail if they would change
    npm run engine:test     check Rust against them

Drift fails on both sides. `src/engine/goldenFixtures.test.ts` fails under
`npm test` if the TypeScript engine stops producing the committed bytes, so a
change is caught where it was made rather than only in a Rust build nobody ran.

## Why the fixtures are shaped as they are

Raw `u32` draws, not floats: `next()` returns `u32 / 2^32`, exact in a double,
so the integer round-trips and no argument about float formatting can arise.

`BrownianWalk` as f64 *bit patterns*: the walk is ordinary arithmetic over
those draws, and recording the bits makes the check exact rather than
approximate.

Ticks, not seconds, in the traces: seconds come from a floating-point multiply
against the tempo map, and two languages need not agree on the last bit of a
double. Ticks are integers and carry the same musical fact.

## Order of work

1. **`rng` — done.** Conformant against 773 fixture lines, with four deliberate
   mutations confirmed to fail the test.
2. `timemap` — ticks and seconds, the boundary the traces depend on.
3. `variables`, `transform` — pure functions over state.
4. `planner` — the heart, and where the traces start passing.
5. `document` — encode and decode, checked against the same v3 fixtures.
6. C ABI and `wasm32`, then Corrosion wires it into the CMake build.

The traces cannot pass until step 4, so until then they are a target rather
than a test.
